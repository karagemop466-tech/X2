Anti-luck — how a lucky result is kept off the leaderboard

Honest framing: luck cannot be removed from a football result. A single game is mostly variance, and a short run of wins is not evidence of skill. What can be done is to make a lucky result unable to pass: bound the uncertainty, count the number of attempts, and test on data that has never been seen. Every test below has a blank current value because no evaluation dataset exists yet.

Method sources

  • NIST 1.3.3.4 Bootstrap Plot — the bootstrap estimates the uncertainty of a statistic, typically with 500 to 1000 resamples, and is not appropriate for every distribution.
  • NIST 7.4.7 Multiple comparisons — repeating pairwise comparisons inflates the overall significance level.
  • NIST 4.4.4 Model validation — a high R-squared does not mean the model fits, and residual analysis is the primary tool.

What would make me trust a strategy

  1. A preregistration committed before any result existed.
  2. A bootstrap interval that excludes the luck-only benchmark, with the resample count stated.
  3. An interval that stays outside the benchmark after the number of tried strategies is accounted for.
  4. The same result in a later block that was never used to choose the strategy.
  5. Errors that do not show structure the model ignored.
  6. A result that holds after real costs, pushes and voids.
