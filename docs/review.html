Review console — choose a path before anything is built

This is the section the brief asks for: a place to review proposals and choose a path before any change is implemented. Each row below is a real decision with three options, the recommended option, the exact file a session would change, what the choice unblocks, and what stays blocked while it is undecided.

How to record a choice. Edit data/decision_choices.json and add, for example:

{"P04": {"choice": "B", "decided_by": "owner", "decided_on": "2026-11-15",
  "reason": "a rule that demotes everything carries no information"}}

Then run python3 scripts/review.py && python3 scripts/build.py. The row changes to DECIDED and keeps your reason and date. Nothing is implemented by recording a choice — it only authorises a later session to do the work.

No choice is pre-filled. 0 of 8 proposals have a recorded choice. The site does not know the owner's mind and does not pretend to.

How to read this table

Do this

  • Read the Stays blocked column first. It tells you the cost of not deciding.
  • Prefer the option whose failure mode is visible. A blank cell is visible; a guessed number is not.
  • Record a choice even when it is "defer". An explicit defer is a decision; silence is not.

Avoid this

  • Choosing Option C anywhere it means scraping a non-official page. That breaks the rule the whole repository is built on.
  • Treating the recommendation as a decision. It is one session's judgement, offered for review.
  • Implementing first and recording afterwards. The point of the console is order.

Every value on this site links to an official source or is marked blank/unverified; project implementation claims link to the repository. Research only. This is not betting advice.
