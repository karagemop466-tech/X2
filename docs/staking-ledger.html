Staking ledger

The brief keeps signal and staking apart so a lucky run of bets cannot disguise a bad forecast. That only works if the two are computed in different places, so this block is produced by its own script and written to a file the ranking step never reads. 1. Assumptions, stated in the file

Payout: flat 1 unit won / 1 unit lost, graded against the project reference line (not a market price). Every unit figure here is a units-against-the-reference-line number under that assumption — not a return, not an ROI, and not comparable with a bookmaker result, because there is no price (Flags F07, F16, F51). A roi_units_pct column is published only because the payout is declared in the same row: it is units divided by stakes under that flat assumption, nothing more. Moneyline rows would need a price to settle and are excluded from the unit ledger entirely.

3. The luck canary

A best-of-family run this large is uncommon under no skill, but the signal gates — not the run — still decide promotion.

The simulation asks the honest version of "could this run be luck": each strategy keeps its own bet count and hit rate and the sequence is redrawn (5000 draws, seed 20261114), so it measures what no skill at all would produce — and it takes the maximum over the whole family, which is where selection bias lives. Under that model the best run among the 7 strategies averages 8.71 units and its 95th percentile is 16; the observed best is 24, reached or beaten by chance in 0.0038 of draws. It assumes independence across strategies, which is conservative here because the strategies share games, so the true spread of lucky runs is wider and this probability is if anything understated.

4. Why the split is structural, not cosmetic

  • The order does not follow the money. M2 ranks 2 on signal and 1 on units won: the staking column moved and the rank did not. Had the run decided the order, a two-unit difference in a coin-flip sequence would have moved a strategy up the board. The divergence column reports this as a watch item rather than silently absorbing it.
  • Uncertainty is shown, not hidden. Units carry a bootstrap interval over the actual sequence (5,000 redraws, a fixed seed, and the file is byte-identical on a re-run); the win-probability interval is the exact one-sided binomial rather than a normal approximation; and the number of decided bets is printed on every row, so a 10-bet record cannot be read as a settled one — R1 (10 bets) and P1 (24) are the two that most need that warning.
  • Nothing here demotes anything. Demotion is a separate gate with its own thresholds, on Demotion gates.
